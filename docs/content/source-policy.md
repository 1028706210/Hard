# 来源快照策略

## 允许的快照字段

`content/sources.yaml` 的每个来源条目只保存 `title`、`url`、`group`、`module_id`、`content_type` 和固定的 `snapshot_date: 2026-08-23`。目录页仅用于提取课程导航中的标题和 URL，并按原始顺序去重。

## 来源与覆盖约束

只接受 `https://www.runoob.com` 的链接。每个目录条目必须恰好归入一个本计划声明的模块；未分类、零归属、多归属、跨域链接，以及任一语言目录为空或 `assigned != expected` 都会使快照失败。

### C# 运算符来源归属冻结合同

- 普通 `+`、`-`、`*`、`/`、`%` 运算符基础知识唯一归入 Task 42 / `csharp-foundations`。
- 用户自定义 `operator overload` 唯一归入 Task 43 / `csharp-oop`。
- 不得为同一来源重复生成两个 lesson，不得多归属或遗留 `unassigned`。
- 内容执行 Agent 无权自行改变上述归属；任何变更必须先由策划总控更新冻结合同。
- 当前来源数据文件的实际映射调整应在经授权的 C# 内容任务中完成，并在 C# 内容统一验收前证明覆盖恰好一次且 `unassigned == 0`；本规划修订不修改产品内容数据。

## 隐私与版权边界

不得提交来源页正文、HTML、图片、评论、广告、Cookie、请求头或临时页面内容。原创性检查在内存中逐页读取来源文本，忽略代码块后标记连续 16 个以上相同中文字符；读取完成后不保留页面内容。

## 网络与审计

目录快照只读取 Python、Java、C# 和 C++ 四个指定目录页。原创性检查仅在对应课程模块已有正文时读取其 front matter 指定的来源 URL；来源页响应不进入仓库、日志或报告。提交前必须确认 Git 未跟踪临时页面文件。
